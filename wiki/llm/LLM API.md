# LLM API

**LLM API** رابطی است که به برنامه‌ها اجازه می‌دهد با مدل‌های زبانی ارتباط برقرار کنند. برخلاف چت کردن در مرورگر، استفاده از API کنترل کامل را فراهم می‌کند: پارامترها را دستکاری می‌کنی، خروجی را در برنامه خودت استفاده می‌کنی و کل فرایند را خودکار می‌کنی.

## الگوی مشترک APIها

| مرحله | توضیح |
| --- | --- |
| ۱. ساخت کلاینت | احراز هویت با کلید API |
| ۲. انتخاب مدل | مشخص کردن نام مدل |
| ۳. ارسال پیام‌ها | فرستادن سیستم پرامپت + پیام کاربر |
| ۴. تنظیم پارامترها | دما، حداکثر توکن و... |
| ۵. خواندن جواب | استخراج متن از پاسخ |

## مکالمه چندنوبتی

مدل‌ها هیچ حافظه‌ای ندارند. هر بار که پیام می‌فرستی، تمام تاریخچه مکالمه دوباره به مدل فرستاده می‌شود. این یعنی:

- هر پیام جدید = ارسال تمام پیام‌های قبلی + پیام جدید
- هزینه به صورت تصاعدی بالا می‌رود
- ممکن است از پنجره کانتکست رد شوی

### راهکارها

- **Sliding Window:** فقط آخرین N پیام را نگه دار.
- **خلاصه‌سازی تاریخچه:** از مدل بخواه خلاصه کند.
- **حافظه خارجی:** اطلاعات مهم را در دیتابیس ذخیره کن.

## استریمینگ (Streaming)

با `stream=True` جواب تکه‌تکه می‌آید (مثل تایپ کردن آدم). مزیت: تجربه کاربری بهتر و پردازش زودتر. هزینه اضافه ندارد.

## چهار عادت حرفه‌ای برای پروداکشن

1. **تلاش دوباره (Retry):** با فاصله‌های فزاینده (Exponential Backoff).
2. **مهلت انتظار (Timeout):** نذار درخواست تا ابد منتظر بماند.
3. **مدل پشتیبان (Fallback):** اگر مدل اصلی جواب نداد، خودکار برو سراغ مدل دیگر.
4. **لاگ کن:** ورودی، خروجی و هزینه را ثبت کن.

## My Understanding

LLM API نقطه تماس بین برنامه و مدل است. درک الگوی مشترک APIها به کمک می‌کند سریع‌تر با ارائه‌دهنده‌های مختلف کار کنی. چهار عادت حرفه‌ای (Retry, Timeout, Fallback, Log) برای ساخت سیستم‌های قابل اعتماد ضروری است.
