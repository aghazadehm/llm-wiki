# User Story Mapping

User Story Mapping is a technique for organizing user stories along the user's journey to build shared understanding and slice releases based on what delivers value. Created by Jeff Patton, it uses a two-dimensional map (activities/tasks horizontally, stories vertically) to ensure teams build a coherent user experience rather than a random collection of features.

## Related Concepts

- [[Impact Mapping]] — provides strategic direction on what to build; user story mapping takes those deliverables and organizes them for delivery.
- [[Example Mapping]] — can be used to break down individual stories found in the map into rules and examples.
- [[Outcome Over Output]] — story mapping helps identify the thinnest slice that delivers value (outcome), not just builds features.
- [[Three Amigos]] — collaborative building of story maps benefits from cross-functional participation.

## My Understanding

A user story map has two dimensions. Horizontally (left to right), it follows the user's journey broken into Activities (big steps) and Tasks (smaller steps within each activity) — this forms the "backbone". Vertically (top to bottom), stories are arranged under each task ordered by priority; the top row represents the most essential version, with additional detail below. 

The key practice is horizontal slicing: draw a line across the map to define a release. The top slice is the walking skeleton/MVP — the thinnest version of the end-to-end experience that delivers real value. This is fundamentally different from vertical slicing by priority list; story mapping ensures each release is coherent from the user's perspective.

Building the map collaboratively is as valuable as the map itself. The process surfaces gaps, redundancies, and misunderstandings before code is written. It also helps distinguish between must-have for the core flow and nice-to-have enhancements.
